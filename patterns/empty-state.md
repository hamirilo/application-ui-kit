# Empty State

## Problem

表示するデータが 0 件のときに、何を出すか。

空状態は「何も表示しない」ことではありません。何も出さないと、読み込みに失敗したのか・データが無いのか・権限が無いのかを利用者が判別できず、そこで行き止まりになります。

**原因**と**次にできる操作**の 2 つを必ず置きます。

## Options

| Option | Choose when | Avoid when |
| --- | --- | --- |
| まだ作られていない | 初回利用・データが 1 件もない | 絞り込みの結果として 0 件になっている |
| 検索・絞り込みの結果が 0 件 | 条件を変えれば結果が出うる | そもそも 1 件も無い（作成を促すべき） |
| 権限がない | 読めるデータはあるが利用者に権限が無い | 作成ボタンを出せてしまう場面 |
| テーブル内の 0 件（`emptyMessage`） | 表の外枠とヘッダーを保ったまま伝えたい | 画面全体が空で、大きく行動を促したい |
| 空状態を出さない（スケルトン／スピナー） | まだ読み込み中 | 読み込みが完了して 0 件と確定している |

## Selection guide

```text
読み込みは完了している？
├─ No  → スケルトンかスピナー（空状態を出すと「無い」と誤解される）
└─ Yes
   ↓
読み込みに失敗した？
├─ Yes → Error State（空状態ではない）
└─ No
   ↓
権限が無くて見えていない？
├─ Yes → 「閲覧権限がありません」＋ 依頼先・申請方法
└─ No
   ↓
絞り込み条件が付いている？
├─ Yes → 「条件に一致する〇〇がありません」＋ 条件をクリアする操作
└─ No  → 「まだ〇〇がありません」＋ 作成ボタン（primary）
```

## Notes

- **「データがありません」だけで終わらせません。** 次にできる操作を必ず添えます。
- **検索結果 0 件と、データ 0 件を同じ文言にしません。** 前者は条件を、後者は作成を促します。この 2 つを書き分けないと、絞り込みすぎたのか元々無いのかが伝わりません。
- 検索結果 0 件では**条件をクリアできる操作**を置きます。何を検索したか忘れて詰まるためです。
- 作成ボタンを置けない場面（権限が無い等）では、**誰に依頼すればよいか**を書きます。
- 読み込み失敗は空状態ではありません。原因と再試行手段が要るので [Error State](error-state.md) を使います。
- テーブルの 0 件は `ApplicationTable` の `emptyMessage` / `emptySubMessage` を使い、外枠とヘッダーを保ちます。表ごと消すと、何の一覧だったかが分からなくなります。
- アイコンは意味の補助です。アイコンだけで状態を伝えません。
- 構成は「見出し」「説明」「次の操作」の 3 点で揃えます。
