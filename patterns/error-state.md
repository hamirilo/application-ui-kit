# Error State

## Problem

読み込み・通信が失敗したときに、何をどこまで壊して見せるか。

エラー表示の目的は謝ることではなく、**利用者が次の行動を選べること**です。何が失敗したか・再試行できるか・できない場合はどこへ問い合わせるかを伝えます。

もう 1 つの論点が**失敗の範囲**です。1 か所の失敗で画面全体をエラーにすると、動いている機能まで使えなくなります。

## Options

| Option | Choose when | Avoid when |
| --- | --- | --- |
| 画面全体（`Empty` + 再読み込み） | その画面の主要データが取得できず、何も表示できない | 一部だけの失敗。動く部分まで使えなくなる |
| 領域単位（カード・パネルの中だけ差し替え） | ダッシュボードの 1 枚など、独立した領域の失敗 | 画面の主要データが取れていない |
| 行・セル単位（バッジ・注記） | 一部レコードだけ集計や取得に失敗した | 全行が失敗している（領域単位にする） |
| トースト（`ApplicationToast` の error） | 保存操作が失敗したが画面自体は生きている | 表示できるデータが無い（消えるので気づけない） |
| 検証エラー（`ApplicationFormField` の `error`） | 入力内容の誤り | 通信の失敗。これはエラーではなく検証 |

## Selection guide

```text
入力内容の誤り？
├─ Yes → 検証（ApplicationFormField の error → Form Layout）
└─ No
   ↓
データは 0 件なだけ？
├─ Yes → Empty State（失敗ではない）
└─ No
   ↓
画面は生きていて、操作だけ失敗した？
├─ Yes → トースト（error）＋ 画面内に状態を残す
└─ No
   ↓
失敗したのは画面の主要データ？
├─ Yes → 画面全体 ＋ 再読み込み
└─ No  → 失敗した領域・行だけをエラーに置き換える
```

## Notes

- **再試行できるならボタンを置きます。** 「再読み込みしてください」と文章で書くだけにしません。
- **技術的なエラー文をそのまま出しません。** 何をすればよいか分かる文にし、問い合わせ用の識別子（リクエスト ID 等）だけを小さく添えます。
- **一部の失敗で画面全体をエラーにしません。** 動いている部分は使えるままにします。
- **再試行が失敗し続ける場合の出口を用意します。** 問い合わせ先・ヘルプへの導線を置きます。
- エラー文は赤字だけに頼りません。アイコンと文章で伝えます（色覚特性・屋外の視認性）。
- 403（権限が無い）と 404（対象が無い）は、再試行しても結果が変わりません。再読み込みボタンではなく、依頼先や一覧へ戻る導線を置きます。
- 保存の失敗をトーストだけで伝える場合、**入力内容を消しません。** トーストは消えるので、画面内にも失敗した状態を残します。
