# Form Layout

## Problem

入力フォームの画面をどう組み立てるか。

部品の使い方ではなく、**画面ごとに毎回決め直しているもの**が対象です。縦の間隔、セクションの切り方、必須表示、ボタンの位置、幅、送信中の扱い。ここが画面ごとに違うと、同じアプリでも入力のたびに勝手が変わります。

入力項目の数と重さによって、そもそも画面にすべきかモーダルにすべきかも変わります。

## Options

| Option | Choose when | Avoid when |
| --- | --- | --- |
| 1 カラムの標準フォーム | 既定。項目が 6 個以下 | 項目が多く、関連ごとにまとまりを付けたい |
| Card でセクション分割 | 項目が 6 個を超え、意味のまとまりがある | 項目が少ない（枠が増えるだけ） |
| 2 カラム | 短い項目（日付・数値・選択）が並び、横に置いても読み返せる | 長文入力・説明が必要な項目。視線が往復する |
| モーダル（`ApplicationFormDialog`） | 項目が 3 個以下で、画面遷移させるほどではない | 入力に時間がかかる、参照しながら書く |
| ステップ分割（ウィザード） | 入力項目が 20 個を超える | 途中で戻って直したい項目が多い |
| テンプレート側のフォーム | サーバーレンダリングの画面 | React でフォーム全体を持っている |

## Selection guide

```text
項目は 3 個以下で、その場で完結する？
├─ Yes → ApplicationFormDialog（モーダル）
└─ No
   ↓
項目は 20 個を超える？
├─ Yes → ステップ分割（ウィザード）
└─ No
   ↓
項目は 6 個を超える？
├─ Yes → Card でセクション分割
└─ No  → 1 カラムの標準フォーム
   ↓
短い項目が連続する？
└─ Yes → その範囲だけ 2 カラム
```

## Notes

決めごとは次のとおり固定します。

| 決めごと | ルール |
|---|---|
| 縦の間隔 | 各項目に `mb-*` を付けず、**親に `space-y-4`** |
| 必須表示 | `ApplicationFormField required`。「任意」は `helpText` に書く |
| ボタンの位置 | 最下部・右寄せ。**キャンセルが左、主アクションが右** |
| ボタンの区切り | `border-t border-border pt-4` |
| 幅 | 1 カラムは `max-w-2xl` 程度。**画面幅いっぱいに伸ばさない** |
| 送信中 | ボタンを `loading`、フォーム全体を `<fieldset disabled>` |

- **フォーム全体を `<form>` で包み `type="submit"` を使います。** `onClick` で送信すると Enter キーで送信できず、ブラウザの入力補完も効きません。
- **エラーは送信後に消しません。** 直すべき箇所が分からなくなります。該当項目を再入力したときに、その項目のエラーだけ消します。
- **バリデーションエラーをトーストで出しません。** どの項目が悪いか伝わりません。全体は先頭のアラート、項目単位は `ApplicationFormField` の `error` です。
- 送信中は `<fieldset disabled>` で囲みます。ボタンを無効化するだけでは入力が編集され続けます。
- **画面幅いっぱいに伸ばしません。** 1 行が長いと目が戻る位置を見失います。
- `autoComplete` を適切に設定します（`name` / `email` / `tel` 等）。補完が効かないフォームは入力ミスが増えます。
- **電話番号・郵便番号・社員番号に `type="number"` を使いません。** `type="text"` + `inputMode="numeric"` を使います（先頭 0 が消える／スピナーが出る）。
- 一覧の中のインライン編集では `ApplicationFormField` を使いません（ラベルが二重になります）。セル内に `ApplicationInput` を直接置きます。

## Catalog
