# Data List

## Problem

複数件のレコードを一覧で見せ、その中から目的の 1 件（または複数件）にたどり着かせる。

一覧そのものは表を描けば済むが、実際に毎回決め直しているのは**表の周りに何をどの順で置くか**です。主アクション・絞り込み・一括操作・件数・ページングの置き場所が画面ごとに違うと、同じアプリでも操作を学び直すことになります。

`ApplicationTable` は表を描くだけで、検索・絞り込み・並び替え・ページングは業務ロジックとして画面側が持ちます。この Pattern が扱うのはその「画面側」です。

## Options

| Option | Choose when | Avoid when |
| --- | --- | --- |
| サーバーレンダリングの一覧 | 既定。件数が多い、絞り込みを URL で表せる、SEO や履歴が要る | 絞り込みのたびに全画面が再読み込みされるのを避けたい |
| `ApplicationTable` + 画面側の絞り込み | 手元の数十件を JS で絞り込み、即座に結果を返したい | 数百行以上（全行描画は重い）、サーバー側ページングが要る |
| 定義リスト（`<dl>`）／カードのリスト | 項目が 2〜3 個で、横に並べるより縦に読ませたい | 列同士を突き合わせて比較したい |
| 表計算的な編集グリッド | セル単位の編集が主目的 | この Pattern の範囲外。専用 UI を検討する |

## Selection guide

```text
件数は数百行を超える？
├─ Yes → サーバー側ページング（全行を描画しない）
└─ No
   ↓
絞り込みを JS で完結させたい？
├─ Yes → ApplicationTable + 画面側で filter/sort
└─ No → サーバーレンダリングの一覧（既定）
   ↓
列を突き合わせて比較する必要がある？
├─ No  → 定義リストかカードのリスト
└─ Yes → 表のまま
```

## Notes

縦の並びは上から次の 5 帯で固定します。

1. 見出し + 主アクション（新規作成）— 右上に `ApplicationButton variant="primary"`
2. 検索・絞り込み — 表の**上**
3. 選択中の件数 + 一括操作 — 選択があるときだけ表示。表の**上**に置く（下だとスクロールで見えなくなる）
4. 表本体 — 空状態を必ず設定する
5. 件数表示 + ページング — 表の**下**

- **空状態は「条件に一致しない」と「1 件もない」を書き分けます。** 同じ文言だと、絞り込みすぎたのか元々無いのかが判別できません（→ [Empty State](empty-state.md)）。
- **`rowKey` を必ず渡します。** 絞り込みで行が入れ替わると、index ベースの key では表示が壊れます。
- **一括操作のボタンは選択 0 件のとき `disabled` にします。** 押せるのに何も起きない状態を作りません。
- **行全体をクリックできるようにするだけで済ませません。** `<tr>` はキーボードでフォーカスできないため、行内にリンクを置きます。
- 行アクションは右端の `ApplicationDropdown`。3 つ以上ならメニューに畳みます。削除は直接実行せず `ApplicationConfirmDialog` を経由します。
- 件数は必ず表示します。何件あるか分からない一覧は信頼されません。
- 絞り込み条件は URL に反映させます（`?status=new` 等）。共有・再訪・戻る操作が壊れなくなります。
- 数値列は `align: 'right'` + `toLocaleString()`。モバイルでは重要でない列に `hidden md:table-cell` を付けて落とします。
