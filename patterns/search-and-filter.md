# Search and Filter

## Problem

一覧を絞り込んで、目的のレコードだけを残す。

難しいのは絞り込みの実装ではなく、**絞り込みが空振りしたときに利用者が自力で立て直せるか**です。検索中や 0 件のときに検索欄が消える・位置が動く・無効化されると、何で検索したのか分からないまま詰まります。

## Options

| Option | Choose when | Avoid when |
| --- | --- | --- |
| キーワード検索（`ApplicationSearchInput`） | 名前・件名など自由入力で絞りたい | 選択肢が固定で、打つより選ぶほうが早い |
| 選択式の絞り込み（`ApplicationSelect`） | ステータス・種別など候補が固定 | 候補が多く、名前で探したい |
| キーワード + 選択式の併用 | 母数が大きく、軸が 2 つ以上ある | 条件が 1 つで足りる（UI が重くなるだけ） |
| 候補から 1 件選ぶ（`ApplicationCombobox`） | 「絞り込み」ではなく**単一選択**が目的 | 結果を一覧として残したい（それは絞り込み） |
| 全画面横断の検索 | アプリ全体を対象に探す | 特定の一覧を絞る用途。この Pattern の範囲外 |

## Selection guide

```text
目的は「1 件を選ぶ」？
├─ Yes → Combobox（→ Single Choice）
└─ No（結果を一覧として残す）
   ↓
候補は固定の選択肢だけ？
├─ Yes → Select 単体（検索欄は要らない）
└─ No
   ↓
絞り込みの軸が 2 つ以上ある？
├─ Yes → キーワード + Select の併用
└─ No  → キーワード検索だけ
```

## Notes

- **検索欄・件数・結果は同じ場所に留めます。** 結果が変わっても位置を動かしません。
- **検索中に検索欄を無効化しません。** 入力し直せなくなります。差し替えるのは結果領域だけです。
- **0 件でも検索欄と件数を残します。** 消すと何で検索したのか分からなくなります。
- 件数は「N 件」と数字で出します。「見つかりました」だけでは何件か分かりません。0 件でも消しません。
- 0 件の表示は [Empty State](empty-state.md) の「検索結果 0 件」を使い、**条件をクリアできる操作**を必ず置きます。
- クリアは `onClear` を渡します（値があるときだけ × が出ます）。条件が付いているときだけ「クリア」を出します。
- 選択中の条件は結果の**上**に出します。何で絞られているかが見えないまま結果だけ変わるのが一番混乱します。
- 検索対象を明示します（`placeholder` に「件名で検索」のように書く）。何が引っかかるか分からない検索欄は使われません。
- 入力の都度リクエストを投げる場合は debounce します（実装側の責務）。
- 検索欄にはラベルを置かず `aria-label` を付けます。
